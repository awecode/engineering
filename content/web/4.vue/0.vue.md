## Vue.js Conventions

1. **Core Principles**
   - Use Composition API exclusively. Do not use Options API.
   - Always use `<script setup>` syntax for Composition API.
   - Use TypeScript for all Vue files and JavaScript code.

2. **Component Structure**
   - Use Single File Components (SFC) with the .vue extension.
   - Order template, script, and style tags consistently:

     ```vue
     <script setup lang="ts">
     </script>

     <template>
     </template>

     <style scoped>
     </style>
     ```

   - Use PascalCase for component names in both file names and imports.

3. **TypeScript Usage**
   - Define prop types using runtime props declaration:

     ```typescript
     const props = defineProps<{
       title: string
       count?: number
     }>()
     ```

   - Use `defineEmits` for type-safe emits:

     ```typescript
     const emit = defineEmits<{
       (e: 'change', id: number): void
       (e: 'update', value: string): void
     }>()
     ```

   - Leverage TypeScript for computed properties, methods, and reactive variables.

4. **Component Communication**
   - Use props for passing data down to child components.
   - Use slots for passing HTML or other components to child components.
   - Do not mix props and slots: props are for data, slots are for template content.

5. **State Management**
   - Use `ref` for primitive values and `reactive` for objects.
   - Prefer `computed` for derived state.
   - For global state, use Pinia with the Composition API setup.

6. **Composables**
   - Extract reusable logic into composables.
   - Name composables with the prefix `use` (e.g., `useUser`, `useCart`).
   - Keep composables focused on a single responsibility.

7. **Event Handling**
   - Use kebab-case for emitted event names.
   - Prefer `@` shorthand over `v-on:` in templates.

8. **Directives**
   - Use directive shorthands: `:` for `v-bind:`, `@` for `v-on:`, and `#` for `v-slot:`.
   - Use `v-for` with a `:key` attribute.
   - Avoid `v-if` on the same element as `v-for`.

9. **Styling**
   - Use scoped styles or CSS modules to avoid style leakage.
   - Use kebab-case for class names.
   - Prefer using utility classes from your CSS framework (if any) over writing custom CSS.

10. **Performance**
    - Use `shallowRef` and `shallowReactive` for large, nested objects that don't need deep reactivity.
    - Implement `v-once` for content that never changes.
    - Use `defineAsyncComponent` for code-splitting.

11. **File and Folder Structure**
    - Group components by feature or route.
    - Use index.ts files for cleaner imports.
    - Keep all global components in a `components` directory.

12. **Testing**
    - Write unit tests for complex computed properties and composables.
    - Use Vue Test Utils with TypeScript for component testing.
    - Implement end-to-end tests for critical user flows using TypeScript-supported tools like Cypress.

Remember to adapt these guidelines to fit your specific project needs and team preferences.
